# The sample corpus

Two kinds of document. Two illustrated books, one of which is what the
application opens with, and four W3C specifications.

Each book's plates stand under its own name, `images/alice/` and
`images/huck/`, because every archived book calls its pictures folder
`images` and both of these have a `cover.jpg`.

## The books

`alice` is *Alice's Adventures in Wonderland* by Lewis Carroll, illustrated by
John Tenniel, in the 1916 Sam'l Gabriel Sons & Company edition, with 28 plates.

It is here because a specification is made of headings, paragraphs and tables
and says nothing about placing a picture. A book does: plates that stand on
their own, illustrations the text runs around on either side, and every one of
them wider than the column it has to go in, so the measure and not the file
decides how large it is drawn.

Fetched 18 August 2026 from `https://www.gutenberg.org/ebooks/19033`, with the
plates from `https://www.gutenberg.org/cache/epub/19033/images/`.

### Copyright

The Alice text was published in 1865 and the illustrations were drawn for it.
Both, and the 1916 edition they are reprinted in, are in the public domain,
which is the only kind of work Project Gutenberg distributes.

The archive's own wrapping is not part of the work and is not kept here: the
header, the footer and the Project Gutenberg licence are dropped by the
conversion, which is why nothing in the derived files carries the trademark or
asks anything of whoever reads them. Project Gutenberg is not the author,

scan came from.

`huck` is *Adventures of Huckleberry Finn* by Mark Twain, illustrated by
E. W. Kemble, the 1884 first edition, with 178 illustrations. Six hundred
thousand characters against Alice's fifty-six, so it is what paging a whole
book costs rather than a chapter, and the pictures are frequent enough that
almost every page has to place one.

Fetched 18 August 2026 from `https://www.gutenberg.org/ebooks/76`, with the
illustrations from `https://www.gutenberg.org/cache/epub/76/images/`. The
text was published in 1884 and the illustrations were drawn for it; both are
in the public domain. Its cached page is as fetched, with nothing removed.

### What the cached page is

`source/alice/alice.html` is that page as fetched, with one block removed: a
table of links to other Project Gutenberg editions of the same book, which
sits in the front matter and is about the archive rather than about Alice.
The place it stood is marked with a comment. The plates are not cached
separately; they are the files under `images/`, which is where the documents
point and where the application reads them from.

## The specifications

Four W3C specifications, each written in all four formats the codecs read.
They are here because paging a document only raises interesting questions once
the document is long enough to have pages: where a heading may sit, what
happens to a table that will not fit, whether a list may be split. Each of
these runs to somewhere between ten and thirty pages.

| `xml-names`      | Namespaces in XML 1.0 (Third Edition)            | 2009 W3C  |
| `xmlbase`        | XML Base (Second Edition)                        | 2009 W3C  |
| `xml-stylesheet` | Associating Style Sheets with XML documents 1.0  | 2010 W3C  |
| `xinclude`       | XML Inclusions (XInclude) Version 1.0            | 2006 W3C  |

Fetched 30 July 2026 from `https://www.w3.org/TR/<name>/`. The pages as
fetched are kept under `source/`, so building the corpus needs no network and
gives the same result every time.

## The roff documents

`markwrite.1` is a manual page for the word processor and `ranges.ms` a short
paper on the range algebra it rests on, both written for this corpus on 8
September 2026 and part of markwrite's own licence.

`htpasswd.1` is a page from the shelf, so that the corpus holds a page
written by somebody else with what pages have in the wild: macros of its
own, conditionals, the escaped dashes and doubled font changes a generator
writes. It is the `htpasswd(1)` page of the Apache HTTP Server, taken on 8
September 2026 from `/usr/share/man/man1/htpasswd.1` as macOS installs it,
generated by the Apache project from its XML documentation. It is used under
the Apache License, Version 2.0 (https://www.apache.org/licenses/LICENSE-2.0),
which permits redistribution with this notice; Copyright The Apache Software
Foundation. It is kept as it was installed, byte for byte.

Each roff document is the source of the four files beside it, which the
codecs write from it:

```
cd packages/markwrite_codecs
dart run tool/roffed.dart ../../samples
```

The tool reads each roff file with its package's codec, writes it with the
XML, HTML, Markdown and LMNL codecs, and reads each back before keeping it.
A manual page's title line becomes a `head` element the other notations
carry as one; what a package does not know is not written, since it showed
nothing.

## What the conversion does and does not keep

The words are kept. The presentation is not: navigation, styling, images and
the specifications' own class attributes are dropped, and the structure is
reduced to what all four codecs can say between them.

Elements kept: `h1` `h2` `h3` (deeper headings become `h3`), `p`, `ul` `ol`
`li` (definition lists become lists), `table` `tr` `th` `td`, `pre`,
`blockquote`, `em` `strong` `code`, and `a` with its `href`.

Tables are kept in all four. Markdown holds them the extended way, as rows of
cells between bars under a line of dashes, which is what GitHub and pandoc
read. A specification's tables are not always square: some rows carry fewer
cells than the head above them, and extended Markdown reads a short row as one
with empty cells at the end rather than refusing it.

## Rebuilding

```
cd packages/markwrite_model
dart run tool/corpus.dart ../../samples
```

A book is kept in a folder of its own under `source/`, named for the document
it becomes, since it arrives with pictures and one flat directory would mix
one book's plates with another's.

Only the XML is written by hand. It is then read with the XML codec and
written back out by each of the others, so all four say the same thing, and
each is escaped by the codec that has to read it rather than by the tool
guessing how.

## What a link can reach

An archived book marks a chapter with an empty anchor standing in front of
it, `<h2><a id="chap01"></a>CHAPTER I.</h2>`, or beside a plate. The anchor
holds nothing, so it goes; its name goes onto whatever it was standing in
front of, which is where a reader following the link wants to arrive. Where
a picture already carried a name of its own, the anchor's wins: an archive
names its pictures after their files and its anchors after what the text
calls them, and it is the anchors the links point at.

Huck points inside itself two hundred and sixteen times and every one of
them now reaches something. In XML, HTML and LMNL it reaches it by name.

Markdown is the exception, and honestly so. This subset has no way to write
an attribute, so a Markdown document can say where a link goes and cannot
say what a link arrives at: `huck.md` keeps all two hundred and sixteen
links, and following one reports that nothing in the document answers to it.
That is what any plain Markdown reader does with the same file.
